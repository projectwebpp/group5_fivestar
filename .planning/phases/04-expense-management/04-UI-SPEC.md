# Phase 4 — UI Design Contract

> Visual and interaction contract for the Expense Management frontend. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none |
| Icon library | Unicode glyphs (inline, no external library) |
| Font | system sans-serif (`fontFamily: 'sans-serif'`) |

**Source:** CONTEXT.md Claude's Discretion + Phase 1/2 established pattern (minimal inline styles, no CSS framework). Confirmed by `components.json` absence and `HomePage.tsx` / `AuthPage.tsx` baseline.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, date label padding |
| sm | 8px | Filter input gaps, inline button padding, date group header vertical padding |
| md | 16px | Default element spacing, gap between list cards (mobile), card internal padding gap |
| lg | 24px | Card padding (horizontal + vertical), page content top padding |
| xl | 32px | Section breaks between filter bar and list |
| 2xl | 48px | Page-level bottom padding (above mobile tab bar clearance) |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Amount input display font context: padding `24px 24px 24px` on the amount card — uniform lg padding on all sides.
- Touch targets for Prev/Next pagination buttons: minimum 48px height (meets WCAG 44px minimum, rounded up to scale).
- Back/cancel button on form header: 48×48px touch target (scale-aligned, meets accessibility minimum).

---

## Typography

All sizes use `fontFamily: 'sans-serif'`. No external font loaded.

**Weight contract: exactly 2 weights.**
- 400 (regular) — all body copy, labels, muted sub-labels, helper text, date group headers, pagination indicator
- 700 (bold) — all headings, button labels, CTAs, and the prominent amount display

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 15px | 400 (regular) | 1.5 | List card category name, description text, filter labels, form field labels |
| Label | 13px | 400 (regular) | 1.4 | Muted sub-labels (date group headers, filter toggle label, pagination "Page X of Y"), form field helper text |
| Heading | 22px | 700 (bold) | 1.2 | Page title ("Expenses", "Add Expense", "Edit Expense", expense detail heading) |
| Display | 36px | 700 (bold) | 1.1 | Amount on detail view and form amount field (prominent large number matching mockup) |

**Source:** Derived from `app.jsx` and `add-screen.jsx` mockup font-size declarations. Weights collapsed to 2-step contract per design system constraint.

## Color

The mockup defines a "cream" light theme as default. All values below are from the cream theme in `app.jsx`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F4EFE6` | Page background (`bg`) |
| Secondary (30%) | `#FFFCF7` | Card backgrounds, form card surfaces (`cardBg`) |
| Surface variant | `#EDE7DA` | Collapsed filter bar background, sub-surfaces, active nav bg (`subBg`) |
| Ink (text) | `#1F1B16` | All primary text, headings, amounts |
| Muted (text) | `#7A7064` | Secondary labels, date group headers, placeholder text, pagination indicator |
| Divider | `rgba(31,27,22,0.07)` | Card internal row dividers, filter bar border |
| Card border | `1px solid rgba(31,27,22,0.04)` | Expense list cards, form cards |
| Card shadow | `0 1px 2px rgba(31,27,22,0.04), 0 8px 24px rgba(31,27,22,0.04)` | Expense list cards, form cards |
| Accent (10%) | `oklch(48% 0.10 195)` (teal) | Reserved for specific elements — see below |
| Destructive | `#C0392B` (standard web red, ~oklch 45% 0.18 25) | Delete button, error messages only |

**Accent reserved for:**
1. Primary CTA button fill ("Add Expense" in header, "Save Expense" / "Save Changes" form submit)
2. Active filter "Apply" button fill
3. App logo ฿ badge background in sidebar/header
4. "View all" / "See detail" link text color (text-only, no fill)
5. Active pagination button border or indicator (if styled differently from disabled)

**Accent is NOT used for:** card backgrounds, filter inputs, secondary buttons, pagination Prev/Next fills, or any decorative purpose.

**Destructive reserved for:** "Delete Expense" button on detail page, inline "Confirm Delete" button (the confirming step), and the inline form validation error message text.

**Primary focal point for ExpensesPage:** The accent-colored "Add Expense" button in the page header is the primary focal point — it must be the most visually prominent interactive element on the list screen.

**Source:** `app.jsx` `makeTheme()` cream theme values. CONTEXT.md D-12, D-14.

### Reusable Components (new in Phase 4)

| Component | Props | Description |
|-----------|-------|-------------|
| `ExpenseCard` | `expense`, `onClick` | Single expense row card: ฿ amount (bold, accent-colored? — no, ink-colored) + category name + date |
| `FilterBar` | `open`, `onToggle`, `filters`, `onApply` | Collapsible panel; "Filters" toggle button + date range + category dropdown + amount range inputs + Apply button |
| `Pagination` | `page`, `totalPages`, `onPrev`, `onNext` | Prev / Next buttons + "Page X of Y" label |
| `EmptyState` | `filtered` | Text message + "Add Expense" button; copy varies if filtered (see Copywriting) |

| `LoadingButton` | `loading`, `label`, `onClick` | Button that shows spinner/disabled state while awaiting API; consistent with Phase 2 pattern |

### Expense Card Layout (D-01, D-02)

```
┌─────────────────────────────────────────────┐
│  ฿ 250.00          Food & Drink    10 May    │
└─────────────────────────────────────────────┘
```

- Amount: left-aligned, 15px bold (700), ink color, ฿ symbol prepended with space ("฿ 250.00")
- Category name: center or flex-spaced, 15px regular (400), muted color
- Date: right-aligned, 13px regular (400), muted color, formatted as "10 May" or "DD MMM"
- Card: `borderRadius: 16px`, card background (`#FFFCF7`), card border, card shadow
- Card padding: 16px horizontal, 16px vertical
- Cards stacked vertically with 8px gap between them

### Filter Bar (D-05, D-08)

- "Filters ▼" / "Filters ▲" toggle button: 13px, regular weight (400), subBg fill, 8px padding, 8px border-radius
- When open: filter inputs appear in a card panel below the toggle, 16px padding, subBg background
- Filter fields: Date From, Date To (type="date"), Category (select dropdown), Amount Min, Amount Max (type="number" step="0.01")
- Apply button: accent fill, white text, 700 weight, 14px, 8px×16px padding, 12px border-radius

### Pagination (D-06, D-07)

- Three elements in a horizontal row: [← Prev] [Page 2 of 8] [Next →]
- Prev/Next: secondary style (subBg fill, ink text, 700 weight), 48px min-height touch target, 12px border-radius
- Page indicator: 13px, muted color, regular weight (400)
- Prev disabled (page 1): opacity 0.4, cursor not-allowed
- Next disabled (last page): opacity 0.4, cursor not-allowed
- Fixed 10 items per page — no page-size control (D-07)

## Interaction Contracts

### Navigation Flow

```
/expenses (list)
  ├── click card → /expenses/:id (detail)
  │     ├── "Edit" button → /expenses/:id/edit (edit form)
  │     │     └── save success → /expenses (list)
  │     └── delete confirm → /expenses (list)
  └── "Add Expense" button → /expenses/new (add form)
        └── save success → /expenses (list)
```

- After successful save (add or edit): redirect to `/expenses` (D-10)
- After successful delete: redirect to `/expenses` (D-11)
- Browser back from detail/form returns to list (standard browser history)

### Form Validation (D-12)

- Validation fires on submit, not on change
- Single consolidated error message displayed inline below the submit button
- Error message: 14px, destructive color (`#C0392B`), regular weight (400)
- Error clears when user begins correcting fields (or on next submit attempt)
- Required fields: amount (> 0, max 2 decimals), category (must be selected), date (required)
- Optional field: description (text, no length limit enforced in UI beyond backend 255 char)

### Delete Confirmation (D-11)

- Initial state: "Delete Expense" button (destructive color fill or destructive color text on subBg)
- After clicking: button replaced inline with "Confirm Delete" (destructive fill) + "Keep Expense" (subBg fill) side by side
- No modal, no `window.confirm()` — pure boolean state toggle (`showDeleteConfirm`)
- Confirmed: API call fires, on success redirect to `/expenses`
- Cancelled: returns to initial Delete button state

### Loading States

- Form submit button: disabled + shows "Saving..." text during API call (consistent with Phase 2 `AuthPage` loading button pattern)
- List page: shows "Loading..." text (or skeleton placeholder at implementer's discretion — plain text acceptable for MVP)
- Delete confirm button: disabled + "Deleting..." during API call

### Date Input (CLAUDE.md constraint)

- All date fields use `<input type="date">` — renders browser-native date picker
- Value stored and sent as ISO YYYY-MM-DD (CLAUDE.md)
- Default value on Add form: today's date (pre-filled)
- Display in list card: formatted as "DD MMM" (e.g., "10 May") — not ISO format shown to user

### Amount Display (D-14)

- Format: "฿ 250.00" — ฿ symbol + space + number formatted to 2 decimal places
- Amount input on form: `<input type="number" step="0.01" min="0.01">` with ฿ symbol displayed as adjacent text, not inside the input
- Amount is prominent (Display size: 36px, weight 700) on the form, normal size (15px bold 700) on list cards, large (22px, weight 700) on detail page

### Category Dropdown on Form

- Populated via `GET /api/categories` on component mount, using same axios JWT interceptor
- Shows: category name (+ icon/color from Phase 3 data if available)
- Select element: full-width, 15px, subBg background, card border, 8px padding, 8px border-radius
- Loading state: disabled select with "Loading categories..." placeholder option
- If fetch fails: show inline error above the select, "Failed to load categories. Refresh and try again."

## Constraints Carried Forward

These are hard constraints from CLAUDE.md and CONTEXT.md that the executor must not violate:

| Constraint | Specification |
|------------|---------------|
| No CSS framework | Inline styles only — no Tailwind, no Bootstrap, no CSS modules |
| No shadcn | Not initialized; do not add `components.json` |
| No modal library | Delete confirm is inline state toggle only |
| Currency UI hidden | No currency selector — backend stores "THB" silently (D-13) |

| Amount validation | > 0, max 2 decimal places (CLAUDE.md) |
| Page size fixed | 10 per page, no user control (D-07) |
| Filter: Apply-only | No auto-apply on input change (D-08) |
| Delete on detail only | No delete from list card (D-11, Deferred list) |
