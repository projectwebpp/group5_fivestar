The exact method to add (per D-05, D-03, D-04, and RESEARCH patterns):

```php
    public function export(): \Symfony\Component\HttpFoundation\StreamedResponse
    {
        $userId = Auth::id();

        $expenses = Expense::where('user_id', $userId)
            ->with('category')
            ->orderBy('expense_date', 'desc')
            ->orderBy('id', 'desc')
            ->get();

        $filename = 'expenses-' . now()->format('Y-m-d') . '.csv';

        return response()->streamDownload(function () use ($expenses) {
            $handle = fopen('php://output', 'w');

            // Header row — 7 columns per D-05 (date, category, description, amount, currency, notes)
            fputcsv($handle, ['date', 'category', 'description', 'amount', 'currency', 'notes']);

            // Data rows — empty $expenses produces header-only CSV per D-04
            foreach ($expenses as $expense) {
                fputcsv($handle, [
                    $expense->expense_date?->format('Y-m-d'),
                    $expense->category?->name ?? '',
                    $expense->description,
                    number_format((float) $expense->amount, 2, '.', ''),
                    $expense->currency,
                    $expense->notes ?? '',
                ]);
            }

            fclose($handle);
        }, $filename, ['Content-Type' => 'text/csv']);
    }
```

Key implementation constraints (do not deviate):
- Use `->with('category')` for eager loading — NOT `->join()` or `->leftJoin()`
- Use `$expense->category?->name ?? ''` — NOT `$expense->category_id` (per pitfall 5 in RESEARCH)
- Use `number_format((float) $expense->amount, 2, '.', '')` — the fourth arg `''` disables thousands separator (per pitfall 4)
- Use `fputcsv()` — do NOT concatenate CSV strings manually (per D-13 / RESEARCH dont_hand_roll)
- Use `response()->streamDownload()` — NOT `response()->success()` (sole JSON envelope exception per D-15 and canonical_refs)
- CSV columns MUST be exactly 7 in this order: date, category, description, amount, currency, notes
- `$expense->expense_date?->format('Y-m-d')` — nullable-safe operator because expense_date is a Carbon cast

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → auth:api middleware | JWT Bearer token must be valid; middleware rejects invalid/expired tokens before export() runs |
| export() → DB | Query is scoped to Auth::id(); user cannot access another user's expenses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information Disclosure (IDOR) | ExpenseController::export() | mitigate | `Expense::where('user_id', Auth::id())` — all queries scoped to authenticated user's ID; no user-supplied ID parameter accepted |
| T-07-02 | Information Disclosure | GET /api/expenses/export | mitigate | Route inside `auth:api` middleware group — unauthenticated requests receive 401 before reaching controller |
| T-07-03 | Information Disclosure | JWT in URL | mitigate | Axios responseType:'blob' with Authorization header — token never appears in URL, server logs, or browser history |
| T-07-04 | Tampering (CSV injection) | fputcsv output (description, notes, category fields) | accept | fputcsv wraps fields in quotes and escapes embedded quotes per RFC 4180. Leading `=`,`+`,`-`,`@` in user-entered text fields are not stripped. For a personal expense tracker where users only export their own data, the injection target is the user themselves — risk accepted. |
| T-07-05 | Elevation of Privilege | Route matching | mitigate | `expenses/export` registered before `expenses/{id}` in api.php — the string "export" cannot be matched as an integer ID, preventing accidental show() invocation |
</threat_model>
