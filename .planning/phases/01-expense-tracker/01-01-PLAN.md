# Phase 01 — Expense Tracker: Core Backend API

## Goal

Implement the full Laravel REST API backend for the Expense Tracker application, covering all 6 resource groups defined in SPEC.md. The API must be usable by the React frontend for the MVP demo and support extension to full feature set.

## Context

Imported from SPEC.md (project root). Tech stack: React (TypeScript) + Laravel (PHP) + MySQL + JWT + Vercel.
DB: MySQL (confirmed over SQLite suggestion in SPEC.md data storage section).
Merge conflict in SPEC.md resolved to HEAD side; Vercel deploy target noted separately.

  - id INT PK AUTO_INCREMENT
  - name VARCHAR(50) NOT NULL UNIQUE

  - id INT PK AUTO_INCREMENT

### 3. Expenses API

Routes: `POST /api/expenses`, `GET /api/expenses`, `GET /api/expenses/:id`, `PUT /api/expenses/:id`, `PATCH /api/expenses/:id`, `DELETE /api/expenses/:id`

- [ ] 3.1 `POST /api/expenses` — validate: amount>0 max 2dp, expenseDate ISO format not required-future (configurable), categoryId exists, currency valid code; return 201 with created record
- [ ] 3.2 `GET /api/expenses` — filters: from, to, categoryId, currency, minAmount, maxAmount, page, limit, sortBy, sortOrder; return paginated list
- [ ] 3.3 `GET /api/expenses/:id` — return single or 404
- [ ] 3.4 `PUT /api/expenses/:id` — full update, same validation as POST
- [ ] 3.5 `PATCH /api/expenses/:id` — partial update; validate only provided fields; ensure resulting record is consistent
- [ ] 3.6 `DELETE /api/expenses/:id` — return 404 if not found

Edge cases handled: amount≤0 → 400; invalid date format → 400; categoryId not found → 404/400; currency not supported → 400; description empty when required → 400.

---

### 4. Categories API

Routes: `POST /api/categories`, `GET /api/categories`, `PUT /api/categories/:id`, `DELETE /api/categories/:id`

- [ ] 4.1 `POST /api/categories` — validate: name required unique (trim+normalize) max 50 chars; color valid HEX if provided; icon in allowed set if provided; return 201
- [ ] 4.2 `GET /api/categories` — return all categories
- [ ] 4.3 `PUT /api/categories/:id` — update, re-validate uniqueness excluding self
- [ ] 4.4 `DELETE /api/categories/:id` — check no expenses reference it; if referenced → 409 with message; otherwise delete

Edge cases: duplicate name (case-insensitive trimmed) → 409; name > 50 chars → 400; invalid HEX color → 400; delete category in use → 409.

### 5. Budgets API

Routes: `POST /api/budgets`, `GET /api/budgets`, `GET /api/budgets/:id`, `PUT /api/budgets/:id`, `DELETE /api/budgets/:id`

- [ ] 5.1 `POST /api/budgets` — validate: limitAmount>0, month format YYYY-MM, categoryId exists, unique month+category → 409 if duplicate; return 201
- [ ] 5.2 `GET /api/budgets?month=YYYY-MM` — list budgets for month with current spent amount and status (safe/warning/over-budget)
- [ ] 5.3 `GET /api/budgets/:id` — single budget with spend status
- [ ] 5.4 `PUT /api/budgets/:id` — update limitAmount/currency
- [ ] 5.5 `DELETE /api/budgets/:id` — 404 if not found

Edge cases: limitAmount≤0 → 400; duplicate month+category → 409; currency mismatch requires conversion before comparison.

### 6. Reports API

Routes: `GET /api/reports/monthly-summary`, `GET /api/reports/category-breakdown`, `GET /api/reports/trend`, `GET /api/reports/export/csv`, `GET /api/reports/dashboard`

- [ ] 6.1 `GET /api/reports/monthly-summary?month=YYYY-MM` — return totalExpense, currency, byCategory array; empty data → return zeros not error
- [ ] 6.2 `GET /api/reports/category-breakdown?month=YYYY-MM` — return per-category amounts, percentages, transactionCount; suitable for pie chart
- [ ] 6.3 `GET /api/reports/trend?from=DATE&to=DATE` — daily/monthly aggregation for trend graph; handle Dec→Jan rollover correctly; convert to base currency before summing
- [ ] 6.4 `GET /api/reports/export/csv?month=YYYY-MM` — stream CSV with headers; escape commas/quotes/newlines in description; filename with timestamp; return empty CSV with headers if no data
- [ ] 6.5 `GET /api/reports/dashboard?month=YYYY-MM` — aggregate monthly-summary + category-breakdown + budget status in one response

### 7. Recurring Expenses API

Routes: `POST /api/recurring`, `GET /api/recurring`, `GET /api/recurring/:id`, `PUT /api/recurring/:id`, `DELETE /api/recurring/:id`, `POST /api/recurring/:id/run`

- [ ] 7.1 `POST /api/recurring` — validate: repeatType in [daily,weekly,monthly,yearly]; nextRunDate >= startDate; isActive defaults true; return 201
- [ ] 7.2 `GET /api/recurring` — list all recurring templates
- [ ] 7.3 `GET /api/recurring/:id` — single template
- [ ] 7.4 `PUT /api/recurring/:id` — update; if amount changed, define in code whether next run uses new or original value (use latest value)
- [ ] 7.5 `DELETE /api/recurring/:id` — soft-delete or hard-delete with cascade consideration
- [ ] 7.6 `POST /api/recurring/:id/run` — manually trigger expense generation from template; check isActive; use unique key recurringId+runDate to prevent duplicates

Edge cases: invalid repeatType → 400; startDate > nextRunDate → 400; duplicate generation prevention via unique constraint.
