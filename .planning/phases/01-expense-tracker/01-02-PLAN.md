**Step 5 — Create the axios API client:**
Create frontend/src/api/client.ts:
```typescript
import axios from 'axios';

const apiClient = axios.create({
  baseURL: import.meta.env.VITE_API_URL,
  headers: {
    'Content-Type': 'application/json',
    'Accept': 'application/json',
  },
});

// Request interceptor — attaches JWT token when present.
// Phase 2 will store the token in localStorage under 'auth_token' after login.
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem('auth_token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

export default apiClient;
```

CRITICAL: `baseURL` MUST use `import.meta.env.VITE_API_URL`. Do NOT hardcode any URL string. Do NOT use a relative path like `/api` — that only works with a dev proxy, not on Vercel.

**Step 6 — Create placeholder pages:**

Create frontend/src/pages/HomePage.tsx:
```tsx
import { useEffect, useState } from 'react';
import apiClient from '../api/client';

interface HealthData {
  status: string;
}

interface HealthResponse {
  success: boolean;
  data: HealthData;
  message: string;
}

export default function HomePage() {
  const [apiStatus, setApiStatus] = useState<string>('checking...');
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    apiClient
      .get<HealthResponse>('/health')
      .then((res) => {
        setApiStatus(res.data.data.status);
      })
      .catch(() => {
        setError('API unreachable — check VITE_API_URL');
        setApiStatus('error');
      });
  }, []);

  return (
    <div style={{ fontFamily: 'sans-serif', padding: '2rem' }}>
      <h1>Expense Tracker</h1>
      <p>
        API Status:{' '}
        <strong style={{ color: apiStatus === 'ok' ? 'green' : 'red' }}>
          {apiStatus}
        </strong>
      </p>
      {error && <p style={{ color: 'red' }}>{error}</p>}
      <nav>
        <ul>
          <li><a href="/auth">Auth (Phase 2)</a></li>
          <li><a href="/expenses">Expenses (Phase 4)</a></li>
          <li><a href="/categories">Categories (Phase 3)</a></li>
          <li><a href="/analytics">Analytics (Phase 5)</a></li>
        </ul>
      </nav>
    </div>
  );
}
```

**Step 9 — Create vercel.json for SPA routing:**
Create frontend/vercel.json:
```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```
This file MUST be at frontend/vercel.json (not repo root). It ensures direct navigation to /expenses or /categories returns index.html instead of Vercel 404. Without this, refreshing on any route other than / returns 404 on the deployed Vercel app.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Vercel CDN | Static asset delivery — no trust boundary concerns for Phase 1 scaffold |
| Browser → Railway API | Cross-origin fetch; CORS must be configured on backend (Plan 01-01) |
| localStorage → apiClient interceptor | auth_token read from localStorage; injected as Bearer header in all requests |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | VITE_API_URL in built bundle | accept | VITE_ vars are intentionally public (baked into static bundle); Railway URL is not secret; acceptable for public API |
| T-02-02 | Information Disclosure | auth_token in localStorage | accept | Phase 1 has no auth token yet; Phase 2 will assess XSS risk; for v1 scope, localStorage is acceptable (httpOnly cookie requires backend session, incompatible with stateless JWT) |
| T-02-03 | Spoofing | axios requests without auth | accept | Phase 1 has no protected routes; interceptor is wired but sends no token (localStorage is empty); Phase 2 adds protected routes |
| T-02-04 | Denial of Service | SPA rewrite catches all paths including assets | accept | vercel.json rewrite applies to all routes; Vercel serves static assets before checking rewrites; no DoS risk |
</threat_model>
