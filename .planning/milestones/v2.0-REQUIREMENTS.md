# Requirements: v2.0 — Budget & Export Features

**Milestone:** v2.0
**Scope confirmed:** 2026-05-12
**Phase numbering:** Continues from v1.0 (Phase 6+)

## Requirements

| REQ-ID | Requirement | Priority | Phase |
|--------|-------------|----------|-------|
| REQ-20 | User can set a monthly budget limit per category | Must Have | TBD |
| REQ-21 | User can view current spend vs budget limit per category | Must Have | TBD |
| REQ-22 | System displays over-budget warnings when spend exceeds limit | Must Have | TBD |
| REQ-23 | User can download expense data as CSV | Must Have | TBD |
| REQ-24 | User can create recurring expense entries (auto-log on schedule) | Must Have | TBD |

## Acceptance Criteria

### REQ-20 — Monthly Budget Limits
- User can set a budget limit (amount) for any category for a specific month/year
- Budget limits are per-user, per-category, per-month
- User can update or delete an existing budget limit
- API: POST/PUT/DELETE `/api/budgets` with `{category_id, month, year, amount}`

### REQ-21 — Spend vs Budget View
- Analytics/dashboard shows actual spend alongside budget limit for each category
- Shows remaining budget (limit − spent) or overage (spent − limit)
- Covers current month by default, filterable by month/year

### REQ-22 — Over-Budget Warnings
- UI shows visual indicator (e.g., red highlight, warning icon) when spend ≥ limit for a category
- Warning appears in both the budget view and category list
- No email/push notifications required (visual only)

### REQ-23 — CSV Export
- User can download all their expenses as a CSV file
- CSV columns: date, category, description, amount, currency
- Optional: filter by date range before export
- Endpoint: GET `/api/expenses/export` returns `text/csv` response

### REQ-24 — Recurring Expenses
- User can mark an expense as recurring (daily/weekly/monthly)
- System auto-creates the expense entry on the scheduled interval
- User can view, edit, and delete recurring expense templates
- Entries appear in normal expense list when created

## Constraints (inherited from v1.0)

- MySQL only (no SQLite)
- JWT auth on all endpoints
- API envelope: `{success, data, message}`
- Dates: ISO format (YYYY-MM-DD)
- Amounts: > 0, max 2 decimal places
- Deploy: Vercel
