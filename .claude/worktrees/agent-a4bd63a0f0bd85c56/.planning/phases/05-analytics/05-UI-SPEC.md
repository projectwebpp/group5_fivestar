## Spacing Scale

Declared values (multiples of 4 only). Extracted from existing components.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Label-to-value gap, badge inner padding |
| sm | 8px | Button padding vertical, gap between sibling buttons |
| md | 16px | Card internal padding, input padding, filter bar internal gaps |
| lg | 24px | Page horizontal padding, section vertical gap, card bottom margin |

### New Components

#### `AnalyticsFilterBar`
Inline (always visible — no toggle), replaces the collapsible FilterBar pattern. The analytics page always needs to show the date range.

```
Layout: flex row (wrap on mobile), gap: 8px
Contents:
  [This Month] [Last Month] [Last 3 Months]   From: [date input]   To: [date input]   [Apply]
```

- Pre-set buttons: `padding: '8px 12px'`, `background: '#EDE7DA'`, `border: '1px solid rgba(31,27,22,0.1)'`, `borderRadius: 8`, `fontSize: 13`, `fontWeight: 400`, `cursor: 'pointer'`
- Active pre-set state (currently selected): `background: 'oklch(48% 0.10 195)'`, `color: '#fff'`, `fontWeight: 700`
- Date inputs: same style as FilterBar.tsx inputs — `padding: '8px 8px'`, `borderRadius: 6`, `border: '1px solid rgba(31,27,22,0.1)'`, `fontSize: 15`
- Apply button: exact style from FilterBar.tsx Apply — `padding: '8px 16px'`, `background: 'oklch(48% 0.10 195)'`, `color: '#fff'`, `fontWeight: 700`, `fontSize: 15`, `borderRadius: 12`
- Clicking a pre-set: immediately populates from/to inputs AND fires the Apply action (no extra click needed — per 05-CONTEXT.md `<specifics>`)

#### `SummaryCards`
Three stat cards in a flex row. On narrow screens wrap to stacked.

```
Layout: display flex, gap: 16px, flexWrap: wrap
Each card:
  background: #FFFCF7
  borderRadius: 12
  padding: 16px 24px
  boxShadow: '0 1px 2px rgba(31,27,22,0.04), 0 8px 24px rgba(31,27,22,0.04)'
  border: '1px solid rgba(31,27,22,0.04)'
  flex: 1, minWidth: 120px
```

Card internal layout:
- Label: 13px / 400 / `#7A7064` — "Total Expenses" | "Daily Average" | "Monthly Average"
- Value: 22px / 700 / `#1F1B16` — e.g. "฿5,200.00"
- Amount format: `฿` prefix + `.toFixed(2)` — matches Phase 4 D-14 pattern

#### `CategoryPieChart`
Recharts `<PieChart>` wrapper card.

```
Container card:
  background: #FFFCF7
  borderRadius: 16
  padding: 24px
  boxShadow: '0 1px 2px rgba(31,27,22,0.04), 0 8px 24px rgba(31,27,22,0.04)'
  border: '1px solid rgba(31,27,22,0.04)'

Section heading: "Spending by Category"
  fontSize: 15, fontWeight: 700, color: #1F1B16, marginBottom: 16

Recharts sizing: width="100%" — use <ResponsiveContainer width="100%" height={280}>
Pie: dataKey="percentage", nameKey="name"
  cx="50%", cy="50%"
  outerRadius={110}, innerRadius={0} (filled pie, not donut)
  Each <Cell> gets fill from the hardcoded palette (index % 8)

Tooltip: Recharts built-in <Tooltip>

No static legend (per D-02 — tooltip only).
```

## Interaction Contracts

### Filter: Pre-set Buttons
- Clicking "This Month": compute `date_from = first day of current month (YYYY-MM-DD)`, `date_to = today (YYYY-MM-DD)`. Populate inputs. Fire API call immediately (no separate Apply click).
- Clicking "Last Month": compute first/last day of previous calendar month. Populate inputs. Fire API call immediately.
- Clicking "Last 3 Months": compute `date_from = first day of month 3 months ago`, `date_to = today`. Populate inputs. Fire API call immediately.
- Active pre-set shows accent background to signal which preset is active. Manually editing date inputs clears the active pre-set highlight.

### Filter: Apply Button
- Clicking Apply with custom date inputs: fires API call with the current from/to input values.
- Apply button is always enabled (no validation blocking — empty dates are valid, defaults server-side).
- While loading: Apply button shows `opacity: 0.6`, `cursor: 'not-allowed'`, label stays "Apply" (no loading label — use page-level loading state instead).

### Pie Chart Tooltip
- On hover (desktop) or tap (mobile): Recharts built-in Tooltip activates.
- Content: `{category name}: ฿{total} ({percentage}%)` — e.g. "Food: ฿1,200.00 (34%)"
- `percentage` value comes directly from server (`D-10` — pre-computed, no client rounding).
- Total formatted as `.toFixed(2)` with `฿` prefix.

### Loading States
- Initial page load: show "Loading analytics..." text, hide SummaryCards and CategoryPieChart.
- On Apply click: show "Loading analytics..." text again, hide previous results until response arrives.
- Do NOT show skeleton cards — plain text loading state matches prior phase pattern.

### Error States
- API error: show `<InlineError>` with "Failed to load analytics. Please try again." above the cards section.
- Previous results remain visible below the error message (do not clear on error — allow retry without losing visible data). Exception: on initial load error, there are no previous results to preserve.

## Constraint Reminders for Executor

These are hard constraints enforced by CLAUDE.md and prior phase decisions:

1. **Inline styles only** — no CSS classes, no Tailwind, no CSS modules, no styled-components.
2. **฿ symbol on all amounts** — `฿ {value.toFixed(2)}` — space between symbol and number (matches Phase 4).
3. **ISO dates** — all date params as `YYYY-MM-DD`. Date inputs are `type="date"` — browser returns YYYY-MM-DD automatically.
4. **API envelope** — analytics response arrives as `{ success, data, message }`. Access `response.data.data` (axios) or `response.data` after unwrapping.
5. **No recharts legend** — tooltip only (D-02). Do not add `<Legend>` component.
6. **percentage from server** — do not compute `percentage` client-side. Use `entry.percentage` directly (D-10).
7. **Single endpoint** — `GET /api/analytics/summary?date_from=&date_to=` (D-08). No other analytics endpoints.
8. **ProtectedRoute** — `/analytics` route already wrapped in `RequireAuth` in App.tsx. No change needed.
