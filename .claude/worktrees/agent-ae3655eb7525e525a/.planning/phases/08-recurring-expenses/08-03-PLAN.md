## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser localStorage → RequireAuth | auth_token absence causes redirect to /auth; no server-side token validation at routing level |
| User input → createRecurring/updateRecurring | Form values sent to API; server-side validation in RecurringExpenseController is the enforcement layer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-10 | Spoofing | /recurring route — RequireAuth | mitigate | RequireAuth checks localStorage.getItem('auth_token') and redirects to /auth if absent; consistent with all other protected routes |
| T-08-11 | Tampering | CreateRecurringPayload form values | accept | Type coercions (Number(), parseFloat()) handle basic malformed input; server-side validation in RecurringExpenseController::store() is the authoritative guard |
| T-08-12 | Information Disclosure | InlineError error messages | accept | API error messages are generic (e.g., "Category not found") — no secrets leaked; same pattern as BudgetPage error display |
</threat_model>
