```typescript
export async function exportExpenses(): Promise<void> {
  const res = await apiClient.get('/expenses/export', { responseType: 'blob' });

  const blob = new Blob([res.data], { type: 'text/csv' });
  const url  = URL.createObjectURL(blob);
  const a    = document.createElement('a');

  // Use Content-Disposition filename if CORS exposes it; fall back to client-derived date
  const disposition = res.headers['content-disposition'] as string | undefined;
  const match       = disposition?.match(/filename="?([^"]+)"?/);
  const filename    = match?.[1] ?? `expenses-${new Date().toISOString().slice(0, 10)}.csv`;

  a.href     = url;
  a.download = filename;
  document.body.appendChild(a);
  a.click();
  document.body.removeChild(a);
  URL.revokeObjectURL(url);
}
```

Key implementation constraints (do not deviate):
- Use `apiClient.get(...)` — NOT `fetch()` or a new axios instance (the existing interceptor must attach the JWT)
- `responseType: 'blob'` is a per-request option passed to `apiClient.get` — it does NOT change the shared client
- The `Content-Disposition` header read is optional — the `?? fallback` handles the CORS case where the header is not exposed (pitfall 2 in RESEARCH)
- `URL.revokeObjectURL(url)` MUST be called after `a.click()` to release blob memory (anti-pattern in RESEARCH)
- Do NOT add error handling inside this function — errors propagate to `handleExport` in ExpensesPage (separation of concerns)
- Do not add a blank line between `document.body.removeChild(a)` and `URL.revokeObjectURL(url)` — they must execute in the same synchronous tick after click

| apiClient → backend | Axios interceptor attaches JWT Bearer header; token never appears in URL or download link |
| blob URL → browser filesystem | Object URL is ephemeral (revoked after click); no persistent client-side storage of expense data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-06 | Information Disclosure | JWT in URL | mitigate | Axios responseType:'blob' uses Authorization header — `window.location.href` redirect pattern explicitly avoided per RESEARCH anti-patterns |
| T-07-07 | Information Disclosure | Blob URL persistence | mitigate | `URL.revokeObjectURL(url)` called immediately after anchor click — blob is released from memory; URL cannot be reused |
| T-07-08 | Denial of Service | exportLoading state | accept | Button is disabled while in-flight (`disabled={exportLoading}`) — prevents duplicate concurrent requests. No rate limiting needed for a personal tool. |
| T-07-09 | Spoofing | Content-Disposition filename | accept | Frontend uses server-provided filename if CORS exposes header; falls back to client-derived `expenses-YYYY-MM-DD.csv`. No security boundary crossed — filename is cosmetic only. |
